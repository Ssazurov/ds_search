# ADR-0002: Возможности RAG-агента (агрегатор, режимы ответа, диагностическая карта)

Дата: 2026-09-07
Статус: Принято

## Контекст
Родители не будут сами писать статьи. Рынок перегружен разрозненными источниками
без синтеза. Нужен не контент-сайт, а навигационный хаб + ИИ-консультант поверх
существующих источников (глоссарий, каталог организаций, внешние статьи).

## Решения

### 1. Позиционирование: агрегатор + RAG, не издатель контента
Не копируем чужие статьи целиком (риск ст. 1259/1270 ГК РФ). Формат:
заголовок + краткая аннотация (2-3 предложения) + ссылка на оригинал.
Полные тексты — только с явного разрешения источника (синдикация) или CC-лицензией.

### 2. Information architecture — по этапам жизненного пути семьи
Категории: пренатальный → раннее развитие (0-3) → дошкольный/школьный →
медицинский (по системам) → юридический/льготы → взрослая жизнь.
Мапится на существующие поля глоссария (`Category`).

### 3. Режимы ответа RAG
`response_mode: full | summary` — параметр промпта, retrieval не меняется.
Одни и те же chunks, разный system prompt для генерации (синтез vs буллеты).

### 4. UI-действия в диалоге (не новые endpoints, один `/chat` + `action`)
| Действие | Эффект |
|---|---|
| Кратко/Подробно | response_mode |
| Показать источники | развернуть metadata chunks |
| Ещё источники | повторный retrieval, exclude_ids |
| Искать в интернете | fallback web search при пустом retrieval |
| Объясни проще | re-prompt под уровень пользователя |

### 5. Диагностическая карта (персонализация)
Параметр `patient_profile` (возраст, пол, диагноз, сопутствующие состояния,
этап) добавляется в `/chat` запрос. Используется как:
- фильтр retrieval по metadata (`lifecycle_stage`, `comorbidity_tags`)
- контекст в system prompt для персонализации формулировок
Не отдельный сервис — расширение существующего RAG-контракта.

### 6. Инлайн-цитирование
Ссылки на источник — внутри текста ответа рядом с конкретным утверждением
(Perplexity-style), не только списком внизу. Критично для доверия в медтеме.

### 7. Explicit "источники не покрывают"
Жёсткое правило в system prompt: если retrieved chunks не отвечают на аспект
вопроса — модель обязана сказать "мои источники не содержат ответа", не
дополнять из общих знаний. Приоритет выше UX для медицинского контента.

### 8. Follow-up вопросы
После ответа — 2-3 предложенных кнопки-продолжения, сгенерированные моделью
на основе ответа + profile. Снижает порог для растерянного родителя.

### 9. Экспорт
- **Экспорт ответа** — один ответ ассистента (с источниками) в выбранном формате.
- **Экспорт диалога целиком** — вся сессия (вопросы+ответы+источники).
- **Выбор формата**: PDF (для показа врачу/специалисту), Markdown (для заметок),
  просто текст в буфер (быстрое копирование).
Реализация: рендер существующей истории диалога в шаблон, без изменений в
retrieval/generation слое. PDF — переиспользовать `pdf`-тулинг, не писать своё.

### 10. Query decomposition
Сложный вопрос (несколько тем сразу — напр. диагноз+сопутствующее состояние+этап)
разбивается на 2-5 под-запросов перед retrieval, каждый ищет по своей части,
результат синтезируется в один ответ. Не для простых вопросов — эвристика
или отдельный классифицирующий промпт-шаг определяет необходимость декомпозиции.

### 11. Уровень аудитории (не только длина ответа)
Переключатель "для родителя" / "для специалиста" — меняет не объём, а лексику
и глубину: простой язык vs термины+ссылки на клинrekомендации. Отдельный
параметр `audience: parent | specialist` в system prompt, независим от
`response_mode`.

### 12. Тематические сессии (notebooks)
Диалог привязывается к теме (этап/категория из information architecture,
см. п.2) — отдельный контекст и история на "новорождённый", "школа" и т.д.,
не смешиваются между собой. Профиль (`patient_profile`, п.5) может быть общим
для пользователя и наследоваться в каждую сессию.

## Требования к ingestion (обязательные поля метаданных)
Каждый chunk/источник должен иметь: `source_url`, `license`, `date_indexed`,
`category`, `lifecycle_stage`, `comorbidity_tags` (опционально), `reviewed_by`
(пусто до появления модерации — поле резервируется сразу).

## Последствия
- `ds_ingestion`: схема метаданных расширяется полями выше до начала массовой загрузки.
- `ds_search`: агрегатор-карточки (заголовок+аннотация+ссылка) — отдельный тип
  результата, не полнотекстовый парсинг чужих статей.
- Юридически чисто: агрегация со ссылкой = стандартная практика (аналог Дзен),
  не нарушает авторское право при отсутствии копирования полного текста.
