# ADR-010: RSS-адаптер для автосбора новостей

Дата: 2026-09-16. Статус: принято. Эпик: #156.

## Контекст
Нужны 8 RSS-источников как второй канал кандидатов для новостного
пайплайна (ADR-003, issue #61) в дополнение к SearchProviderChain
(Tavily). RSS отдаёт готовый список записей фида, а не результат по
запросу — под интерфейс `SearchProvider.search(query)` не подходит
концептуально (нет query).

## Решение
- Новый модуль `src/news/rss.py`: `fetch_feed`/`fetch_all` читают
  `config/rss_sources.yaml` (issue #160), парсят через `feedparser`,
  возвращают `RssHit(url, title, source_name, published_at)`.
- Фильтр свежести (issue #158) — параметр `max_age_days` в `fetch_feed`,
  по умолчанию 5. Не отдельный слой, а условие при обходе `entries`.
- Ручной запуск за период N дней (issue #159) — тот же параметр
  `max_age_days`, прокинутый из CLI (`scripts/collect_rss.py --days N`,
  `--days 0` = без фильтра). Отдельного "режима" не вводим — YAGNI.
- Даунстрим (dedup → license-гейт → download_single → LLM-draft →
  news_items) переиспользуется из `src/news/collect.py`: `_collect_one`
  получил необязательный параметр `source_published_at`, RSS передаёт туда
  реальную дату публикации из фида (в отличие от Tavily-хитов, где её нет).
  Новая функция `collect_rss()` в том же модуле — конвертирует `RssHit` в
  `SearchHit` и вызывает тот же `_collect_one`, тот же dedup по
  `news_items.source_url` (issue #47), тот же license-гейт (issue #3).
- Отдельная БД/таблица не нужна — те же `news_items`, тот же
  draft→approve→publish flow (ADR-003), просто ещё один источник
  кандидатов.
- Отдельный cron: `scripts/collect_rss.py`, не смешан с
  `scripts/collect_news.py` — разная частота уместна (RSS можно чаще,
  фиды дешевле поисковой квоты).

## Альтернативы
- Реализовать RSS как `SearchProvider` в `SearchProviderChain` — отклонено:
  `search(query)` семантически не подходит (RSS не ищет по запросу), и
  фильтр свежести/параметр периода не укладывается в интерфейс без костылей.
- Отдельная таблица/БД для RSS-кандидатов — отклонено: `news_items` уже
  дедуплицирует по `source_url` независимо от источника, разделять незачем
  (YAGNI).

## Уточнение
URL фидов в `config/rss_sources.yaml` — первичный список из 8 доменов по
теме (СД/РАС/благотворительность), точность путей `/feed/` не
верифицирована сетевым запросом при написании ADR. Первый ручной прогон
(issue #159) покажет через `stats.errors`, какие фиды не парсятся —
конфиг правится по факту, без нового ADR (это данные, не архитектура).
