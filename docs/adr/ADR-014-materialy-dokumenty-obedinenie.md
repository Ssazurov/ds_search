# ADR-014: Объединение вкладок «Материалы» и «Документы»

Статус: Accepted
Дата: 2026-09-26
Issue: TBD (epic)

## Контекст

«Документы» сканирует ФС (`data/raw/*/*.json`), статус GAR берёт из
локального `gar_document_id`/`ingest_error`. «Материалы» читает GAR API
напрямую (`GarIngestClient.list_documents`).

Уникальное в «Материалах», отсутствующее в «Документах»:
1. Документы в GAR без локального raw-файла.
2. Фильтр по статусу GAR: Активные/Архив/Все.
3. Архивация/разархивация (поштучно и пакетно).
4. Полное удаление из GAR с подтверждением (Документы удаляют только
   локальные файлы).
5. «Перезагрузить из источника» (`reload_by_gar_id`, через ds_ingestion).
6. Редактирование title/summary с PATCH в GAR (карточка).

## Решение

1. Объединить источники в «Документах»: local rows (скан `data/raw/`) +
   GAR-документы без соответствия по `gar_document_id` (merge, не замена).
2. Для строк без локального файла — колонки «MD»/«JSON» пустые (нет ссылки).
3. Перенести во вкладку «Документы»: фильтр по статусу GAR, архивацию/
   разархивацию, полное удаление из GAR, «Перезагрузить из источника»,
   PATCH title/summary.
4. Добавить фильтр «Локально» (да/нет/не выбрано) и кнопку «Сбросить»
   (сброс всех фильтров таблицы).
5. Удалить вкладку «Материалы» (`ui/materials_tab.py`) и её точку входа
   из `ui/app.py`.

## Вне скоупа (отдельные задачи)

- Документы со старыми категориями, отображаемые как `methodology`.
- Баг: в форме редактирования при смене «Направление» список «Категория»
  не обновляется под новое направление.
- Осиротевшие `data/raw/<domain>/` файлы без `DEFAULT_DATA_ROOT` уровня
  (найдены при анализе, не загружены в GAR) — отдельная задача при
  необходимости.

## Порядок реализации

Строгий порядок из-за зависимостей: #295 (merge) блокирует всё остальное
(296–301 без него не на чем показывать GAR-only строки), #302 (снос
«Материалы») — строго последним, после ручной проверки в проде, что все
6 функций реально перенесены и работают.

## Открытые риски (по ревью 2026-09-26)

1. **Производительность merge (#295):** `GarIngestClient.list_documents()`
   на каждый рендер вкладки — лишний сетевой вызов к GAR при ФС-скане,
   который сейчас быстрый. Решение: не дёргать GAR при каждом рендере,
   обновлять GAR-часть списка по явной кнопке «Обновить» (кэш до
   следующего нажатия), аналогично паттерну справочников (ADR-013).
2. **Полное удаление (#299) — две отдельные кнопки, однозначная семантика:**
   - «Удалить из GAR» — вызывает `client.delete_document()`, как сейчас в
     «Материалах»; локальный `data/raw/*.json`/`.md` не трогает.
   - «Удалить везде» — удаляет в GAR (если `gar_document_id` есть) И
     локальный файл; если в GAR документа уже нет (или у строки нет
     `gar_document_id`) — удаляет только локально, GAR не трогает.
   Кнопка «Удалить из GAR» показывается только если у строки есть
   `gar_document_id`. Обе — за отдельным подтверждением с явным русским
   текстом о необратимости и о том, что именно будет удалено.
3. **reload_by_gar_id (#300):** идёт через ds_ingestion — при реализации
   проверить, не требует ли контракт правок на стороне ds_ingestion.

## Последствия

- Один источник правды для управления документами в UI.
- Полное удаление из GAR становится доступно из «Документов» — требует
  аккуратного UI-подтверждения (уже есть паттерн в «Материалах»), с учётом
  риска 2 выше.
